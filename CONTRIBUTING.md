# Руководство по участию в VK Desktop

[Русский](CONTRIBUTING.md) · [English](CONTRIBUTING.en.md)

Спасибо всем, кто помогает развивать VK Desktop: сообщает об ошибках, предлагает
идеи, улучшает документацию или отправляет код.

VK Desktop распространяется как source-available проект, а не как программное
обеспечение с открытым исходным кодом. Перед началом работы ознакомьтесь с
[лицензией](LICENSE), настоящим руководством и
[Кодексом поведения](CODE_OF_CONDUCT.md).

## Способы участия

- **Ошибка:** создайте
  [Issue](https://github.com/yamixdev/vk-desktop/issues) с версией приложения,
  версией Windows, шагами воспроизведения, ожидаемым и фактическим результатом.
- **Новая возможность:** опишите задачу, пользовательский сценарий и ожидаемую
  пользу в Issue.
- **Исправление или документация:** отправьте Pull Request по процессу ниже.
- **Уязвимость или утечка данных:** не публикуйте сведения открыто; отправьте
  описание через [Telegram @ilushadevz](https://t.me/ilushadevz?direct).
- **Сотрудничество или специальное разрешение:** свяжитесь через тот же
  Telegram-аккаунт.

Перед публикацией логов удалите токены, cookies, идентификаторы сессий,
персональные данные и локальные пути, раскрывающие личную информацию.

## Обращения от организаций

Представителям VK и других организаций по вопросам сотрудничества, передачи
прав или специальных разрешений необходимо предоставить проверяемое
подтверждение личности и полномочий. Подойдут письмо с официального
корпоративного домена или подтверждение через другой независимо проверяемый
официальный канал.

Документы, удостоверяющие личность, и другие чувствительные сведения не следует
публиковать в Issues или Pull Request.

## Клонирование и форки

[Лицензия](LICENSE) разрешает клонировать или форкать официальный репозиторий,
создавать рабочие ветки и изменять код для подготовки добросовестного Issue или
Pull Request в `yamixdev/vk-desktop`. Форк можно сохранять столько, сколько это
обоснованно требуется для рассмотрения и сопровождения вклада.

Это разрешение не позволяет:

- выпускать собственные сборки или установщики на основе проекта;
- распространять самостоятельные или производные версии;
- использовать код, название, логотип или другие материалы в коммерческих
  целях без письменного разрешения;
- удалять сведения об авторстве и лицензии;
- выдавать форк за официальный релиз VK Desktop или за полностью собственную
  разработку.

## Перед началом работы

Для новой функции, изменения архитектуры, заметной переработки интерфейса,
updater, безопасности или фонового поведения сначала создайте Issue. Небольшие
исправления ошибок, тестов и документации можно отправлять сразу.

Не добавляйте в репозиторий:

- токены, cookies, пароли, сертификаты и данные профиля Chromium;
- сторонний код, изображения или другие материалы без совместимого разрешения;
- сгенерированные каталоги `dist`, `node_modules` и профили бенчмарков;
- изменения встроенного VK Next без предварительного обсуждения, подтверждения
  происхождения артефакта и обновления integrity metadata;
- несвязанные массовые переформатирования или изменения lock-файла.

## Среда разработки

Основная целевая среда проекта:

- Windows x64;
- Node.js 26;
- npm 11.

```powershell
git clone https://github.com/YOUR_NAME/vk-desktop.git
cd vk-desktop
git remote add upstream https://github.com/yamixdev/vk-desktop.git
npm ci
git switch -c feature/short-description
```

Используйте короткое понятное имя ветки с подходящим префиксом, например
`fix/`, `feature/`, `docs/` или `refactor/`.

## Проверка изменений

Перед отправкой Pull Request выполните:

```powershell
npm run check
```

Добавляйте или обновляйте тесты для изменённого поведения. Длительный
performance-бенчмарк требуется только для изменений, затрагивающих память,
нагрузку CPU, фоновые таймеры или запуск приложения. В таком случае укажите
сценарий измерения, исходные условия и результаты до и после.

## Требования к Pull Request

Pull Request должен:

1. кратко описывать проблему и выбранное решение;
2. содержать инструкции по проверке;
3. ссылаться на связанный Issue, если он существует;
4. перечислять известные риски и ограничения;
5. включать скриншоты для заметных визуальных изменений;
6. обновлять документацию и тесты, когда это необходимо;
7. не смешивать несколько несвязанных задач.

Убедитесь, что в diff отсутствуют секреты, временные файлы и случайные изменения.
Заголовок и описание Pull Request должны позволять понять его назначение без
дополнительной переписки.

## Рассмотрение изменений

Сопровождающие проекта могут запросить правки, предложить другой подход,
отложить рассмотрение либо закрыть Pull Request без слияния. Отправка вклада не
гарантирует его принятие и не устанавливает срок ответа.

Технические решения принимаются с учётом безопасности, сопровождаемости,
производительности, направления проекта и условий лицензирования.

## Права на вклад

Отправляя код, документацию, изображения или другой вклад, участник
подтверждает наличие необходимых прав и принимает раздел **Contributions** в
[LICENSE](LICENSE).

Авторские права на оригинальную часть вклада сохраняются за участником.
Одновременно проекту предоставляется бессрочная лицензия на использование,
изменение, распространение, сублицензирование и перелицензирование этого вклада
в составе VK Desktop. Это необходимо, чтобы проект мог принимать, сопровождать
и распространять присланные изменения.

Отправка вклада не меняет лицензию всего VK Desktop и не предоставляет право
выпускать отдельный продукт на его основе.
